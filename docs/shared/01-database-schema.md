# 01 — Database Schema (Shared PostgreSQL)

One Supabase Postgres database serves both apps. This is the source of truth. All timestamps are `timestamptz` (UTC); all money is `bigint` whole coins.

## 1. Schemas & extensions

```sql
create extension if not exists "pgcrypto";      -- gen_random_uuid()
create extension if not exists "pgjwt";          -- if needed for token helpers
create schema if not exists app;                  -- app data (RLS protected)
create schema if not exists admin;                -- admin/RBAC tables (strict RLS)
create schema if not exists audit;                -- append-only logs
```

- `auth.users` (Supabase Auth) is the identity table. All profile tables reference it by `uuid`.
- RLS is **enabled on every table in `app` and `admin`**. No table is exposed without a policy.
- The mobile apps connect with the **publishable key** (`sb_publishable_…`) and are constrained by RLS. Privileged mutations run inside Edge Functions using the **secret key** and still follow transactional rules.

## 3. Identity & profiles

### `app.users` (mirror/extension of auth.users — do not duplicate auth)
`auth.users` holds email + auth metadata. App-level profile data lives here:

```sql
create table app.profiles (
  id              uuid primary key references auth.users(id) on delete cascade,
  email           text not null,
  display_name    text not null check (char_length(display_name) between 2 and 30),
  app_uid         text unique not null,            -- 4-digit in-app UID ("1234")
  ff_uid          text unique not null,            -- Free Fire UID
  in_game_name    text not null,
  whatsapp_phone  text not null,                   -- E.164 +92…; required, not a login factor
  phone_verified  boolean not null default false,  -- format-only in MVP; future WhatsApp OTP
  avatar_path     text,
  status          user_status not null default 'active',
  referral_code   text unique not null,
  referred_by     uuid references app.profiles(id),
  created_at      timestamptz not null default now(),
  updated_at      timestamptz not null default now()
);
```

- `app_uid` is generated by the server (4 digits; retry on collision, then expand if exhausted).
- `whatsapp_phone` is masked in reads (`+92***1234`) except to finance-authorized admins.
- Email changes require re-verification through Supabase Auth.

## 4. Wallet

```sql
create table app.wallet_accounts (
  profile_id       uuid primary key references app.profiles(id) on delete cascade,
  available_balance bigint not null default 0 check (available_balance >= 0),
  held_balance      bigint not null default 0 check (held_balance >= 0),
  version           bigint not null default 0,   -- optimistic concurrency
  updated_at        timestamptz not null default now()
);

create table app.wallet_ledger (
  id             uuid primary key default gen_random_uuid(),
  profile_id     uuid not null references app.profiles(id),
  direction      ledger_direction not null,
  type           ledger_type not null,
  amount         bigint not null check (amount > 0),
  balance_after  bigint not null,                 -- snapshot
  idempotency_key text unique,                    -- prevents double effects
  reference_type text,                            -- 'tournament','withdrawal',…
  reference_id   uuid,
  note           text,
  created_by     uuid references auth.users(id),  -- admin/system actor
  created_at     timestamptz not null default now()
);
create index on app.wallet_ledger (profile_id, created_at desc);
create index on app.wallet_ledger (reference_type, reference_id);
```

Rules: the wallet balance is **derived** from the ledger but cached on `wallet_accounts` under row lock; a reconciliation job compares them and flags drift (never auto-fixes). See [03-wallet-and-ledger.md](03-wallet-and-ledger.md).

## 17. RLS posture (summary)

- Players may `SELECT` only their own row in `profiles`, `wallet_accounts`, `wallet_ledger`, `registrations`, `match_results`, `notifications`, and only published public data in `tournaments`, `banners`.
- Players may **not** `INSERT/UPDATE/DELETE` any financial, result, room, tournament, or admin table directly. Those go through Edge Functions.
- Admins have **no blanket RLS bypass**. Edge Functions verify the caller's admin roles and permissions, then use the secret key to perform the action.
- `admin.*` and `audit.*` are only reachable through Edge Functions; RLS denies direct client access entirely.
- `rooms.room_password` is excluded from any client-facing view/function result unless the caller is a confirmed, eligible registration for a released room.
